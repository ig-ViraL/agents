# Project Dev Environment

## Bootstrap — viral-agents.md
Project facts (stack, folder map, conventions, key files, commands) live in
`./viral-agents.md` at the project root. This file is auto-generated by the
`project-scout` agent and is gitignored (per-clone, not shared).

- If `viral-agents.md` does NOT exist → run agent: **project-scout** FIRST.
- Every other custom agent loads `viral-agents.md` at the start of its task
  instead of re-scanning manifests and folder trees. This keeps session context
  small and consistent.
- Re-run `project-scout` whenever the stack, folder layout, or major conventions
  change (new framework, new DB, new state lib, restructure).

## Agent Routing Rules

Default flow for any non-trivial work:

```
project-scout  →  requirements-planner  →  backend-dev / frontend-dev  →  test-generator
    (once)            (per feature)              (execution)               (auto)
```

Specific triggers:

- **No `viral-agents.md` in the project root** → run agent: `project-scout` first.
- **New requirement, feature, or vague idea** ("build X", "add Y", "we need Z")
  → use agent: `requirements-planner`. It asks counter-questions, produces a
  plan, gets your approval, then routes to the correct execution agent(s).
- **Backend task** (API, DB, auth, migration, server logic) → `backend-dev`.
- **Frontend task** (component, page, styling, state, routing) → `frontend-dev`.
- **After any feature completes** (backend-dev or frontend-dev outputs the
  handoff block) → automatically invoke `test-generator` with the changed files.
- **Skip `requirements-planner`** only for: trivial one-line edits, pure
  questions about existing code, or tasks where the user has already given a
  clear, scoped plan.

## Global Rules (apply to ALL agents)
- Load `./viral-agents.md` before touching code — never re-detect the stack
- Always read existing code before writing new code
- Follow the project's existing conventions — folder structure, naming, patterns
- Never hardcode secrets or credentials
- TypeScript is preferred; add types everywhere
- Every PR-worthy change needs a brief summary comment at the top of new files
- Use installed skills from marketplaces when they apply to the task
